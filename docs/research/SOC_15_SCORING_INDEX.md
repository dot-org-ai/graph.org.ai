## Scoring Framework Reference

### Four Dimensions Assessed

1. **Action Score** (0.0-1.0 or null): Can an AI make an API call to execute this?
   - 1.0 = AI can execute via tool call
   - 0.5 = Hybrid (AI can initiate, requires physical execution)
   - 0.0 = Requires physical presence

2. **Event Score** (0.0-1.0 or null): Can state changes be represented digitally?
   - 1.0 = All events digitally representable
   - 0.0 or null = Events not digitally representable

3. **Activity Score** (0.0-1.0 or null): Digital/physical mix of ongoing process?
   - 1.0 = Pure digital activity
   - 0.5 = Hybrid digital/physical
   - 0.0 = Pure physical

4. **Result Score** (0.0-1.0 or null): Digital accessibility/representability of output?
   - 1.0 = Digital output
   - 0.5 = Physical with digital representation
   - 0.0 = Pure physical with no digital representation

## Methodology

### Core Principle
**Digital Score = "Can an AI agent make a tool call to execute this?"**

This measures API/tool accessibility for AI agents, not human involvement or physical infrastructure requirements.

### Key Assumptions for SOC 15-0000

1. **Development Tools**: IDEs, version control (Git), deployment pipelines have APIs
2. **Cloud Infrastructure**: AWS, Azure, GCP all provide complete API control
3. **Data Analysis**: Python/R libraries, ML frameworks, Jupyter have programmatic interfaces
4. **Administration**: Kubernetes, Terraform, cloud management tools are API-driven
5. **Security Tools**: SIEM systems, vulnerability scanners, forensics tools have APIs

### Why 0.85-0.99 Range

- **0.99 occupations**: Pure code/data work (no physical dependencies)
- **0.95-0.98 occupations**: Digital work with minor physical elements (infrastructure)
- **0.85-0.90 occupations**: Require human interaction (support, meetings, infrastructure implementation)
