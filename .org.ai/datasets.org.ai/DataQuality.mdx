# Data Quality

Data quality is foundational to analytics, machine learning, and decision-making. High-quality data is accurate, complete, consistent, timely, and fit for purpose. Data quality frameworks provide systematic approaches to measure, monitor, and improve data.

## Overview

Data quality dimensions:

**Accuracy**: Data correctly represents reality
- Are values correct and precise?
- Are calculations correct?
- Do values fall within expected ranges?

**Completeness**: All required data is present
- Are there missing values?
- Are required fields populated?
- What is the null/empty rate?

**Consistency**: Data is uniform across systems
- Are values standardized (e.g., date formats)?
- Are duplicate values handled correctly?
- Are relationships maintained?

**Timeliness**: Data is available when needed
- How fresh is the data?
- What is the latency from source to availability?
- Are SLAs being met?

**Validity**: Data conforms to defined format and structure
- Do values match expected types?
- Do values conform to business rules?
- Are constraints satisfied?

**Uniqueness**: No unintended duplicates
- Are duplicate records identified?
- Are there unintended data copies?
- Is deduplication working correctly?

## Data Validation

### Validation Rules

**Type Validation**:
```python
# Ensure correct data types
rules = {
    "age": {"type": "integer"},
    "email": {"type": "string"},
    "created_at": {"type": "timestamp"},
    "active": {"type": "boolean"}
}
```

**Range Validation**:
```python
# Values fall within acceptable ranges
rules = {
    "age": {"min": 0, "max": 150},
    "score": {"min": 0, "max": 100},
    "created_at": {"before": "now()"}
}
```

**Pattern Validation**:
```python
# Values match expected patterns
rules = {
    "email": {"pattern": r"^[a-zA-Z0-9+_.-]+@[a-zA-Z0-9.-]+$"},
    "phone": {"pattern": r"^\+?1?\d{9,15}$"},
    "zip_code": {"pattern": r"^\d{5}(-\d{4})?$"}
}
```

**Set Membership Validation**:
```python
# Values from allowed set
rules = {
    "status": {"enum": ["active", "inactive", "pending"]},
    "country": {"enum": ["US", "CA", "MX"]},
    "currency": {"enum": ["USD", "EUR", "GBP"]}
}
```

**Relationship Validation**:
```python
# Constraints across fields
rules = [
    {
        "name": "age_must_be_positive",
        "condition": "age >= 0"
    },
    {
        "name": "end_date_after_start",
        "condition": "end_date > start_date"
    },
    {
        "name": "active_requires_start_date",
        "condition": "if status='active' then start_date is not null"
    }
]
```

**Referential Integrity Validation**:
```python
# Foreign key constraints
rules = {
    "customer_id": {
        "foreign_key": "customers.id"
    },
    "order_id": {
        "foreign_key": "orders.id"
    }
}
```

```python

    max_value=150
)

# Run validation
results = df.validate()
```

## Data Testing

### Test Categories

**Schema Tests**:
Verify structure and types.

```python
def test_schema():
    df = load_data()
    assert set(df.columns) == {"id", "name", "email", "age"}
    assert df["id"].dtype == "int64"
    assert df["email"].dtype == "object"
```

**Completeness Tests**:
Check for missing values.

```python
def test_completeness():
    df = load_data()
    required_fields = ["id", "name", "email"]
    for field in required_fields:
        assert df[field].isna().sum() == 0, f"Missing values in {field}"
```

**Accuracy Tests**:
Verify correctness against sources.

```python
def test_accuracy():
    df = load_data()
    source_df = load_source_data()

    # Sample comparison
    sample_ids = [1, 2, 3, 4, 5]
    for id in sample_ids:
        expected = source_df[source_df.id == id].iloc[0]
        actual = df[df.id == id].iloc[0]
        assert expected['name'] == actual['name']
```

**Consistency Tests**:
Check for contradictions.

```python
def test_consistency():
    df = load_data()

    # Created before updated
    assert (df['created_at'] <= df['updated_at']).all()

    # Active requires email
    active_no_email = df[(df['status'] == 'active') & (df['email'].isna())]
    assert len(active_no_email) == 0
```

**Uniqueness Tests**:
Detect duplicates.

```python
def test_uniqueness():
    df = load_data()

    # No duplicate IDs
    assert df['id'].nunique() == len(df)

    # No duplicate records
    assert df.duplicated().sum() == 0
```

**Timeliness Tests**:
Verify data freshness.

```python
def test_timeliness():
    df = load_data()
    last_update = df['updated_at'].max()
    age_minutes = (datetime.now() - last_update).total_seconds() / 60

    assert age_minutes < 60, f"Data is {age_minutes} minutes old"
```

## Anomaly Detection

### Statistical Anomalies

**Z-Score Method**:
```python
import numpy as np
from scipy import stats

def detect_outliers_zscore(data, threshold=3):
    z_scores = np.abs(stats.zscore(data))
    return data[z_scores > threshold]

# Values >3 standard deviations from mean are outliers
```

**IQR Method**:
```python
def detect_outliers_iqr(data):
    Q1 = data.quantile(0.25)
    Q3 = data.quantile(0.75)
    IQR = Q3 - Q1

    lower_bound = Q1 - 1.5 * IQR
    upper_bound = Q3 + 1.5 * IQR

    return data[(data < lower_bound) | (data > upper_bound)]
```

### Distribution Shift Detection

```python
from scipy.stats import ks_2samp

# Compare current distribution to baseline
baseline_data = load_baseline()
current_data = load_current()

statistic, p_value = ks_2samp(baseline_data, current_data)

if p_value < 0.05:
    print("Distribution shift detected!")
```

### Isolation Forest

```python
from sklearn.ensemble import IsolationForest

# Unsupervised anomaly detection
clf = IsolationForest(contamination=0.1)
predictions = clf.fit_predict(X)
anomalies = X[predictions == -1]
```

## Best Practices

1. **Define Clear Requirements**: What does "good" data mean for your use case?
2. **Automate Validation**: Don't manually check data quality
3. **Profile Before Modeling**: Understand data before using it
4. **Monitor Continuously**: Set up ongoing quality monitoring
5. **Document Issues**: Track and categorize quality problems
6. **Root Cause Analysis**: Understand why issues occur
7. **Establish SLAs**: Define and enforce data quality expectations
8. **Test Data Quality**: Include quality tests in your pipeline
9. **Make It Visible**: Dashboard quality metrics for stakeholders
10. **Invest in Data Governance**: Quality is everyone's responsibility
