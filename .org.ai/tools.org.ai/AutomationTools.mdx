# Automation Tools

CI/CD pipelines, testing frameworks, deployment tools, and monitoring systems for automating software delivery and operations.

## Overview

Automation tools enable teams to build, test, deploy, and monitor applications with minimal manual intervention. They form the backbone of DevOps practices, enabling continuous integration, continuous delivery, and reliable infrastructure management.

## Continuous Integration (CI)

### GitHub Actions

GitHub's native CI/CD platform:

```yaml
name: CI Pipeline

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  build-and-test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        node-version: [16.x, 18.x, 20.x]

    steps:
      - uses: actions/checkout@v3

      - name: Use Node.js ${{ matrix.node-version }}
        uses: actions/setup-node@v3
        with:
          node-version: ${{ matrix.node-version }}
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Run linter
        run: npm run lint

      - name: Run tests
        run: npm run test

      - name: Build application
        run: npm run build

      - name: Upload coverage
        uses: codecov/codecov-action@v3
        with:
          files: ./coverage/coverage-final.json
```

**Advantages:**
- Native GitHub integration
- Free for public repositories
- Matrix builds for multiple environments
- Reusable workflows
- Secrets management
- Artifact storage

### Jenkins

Self-hosted CI/CD server:

```groovy
pipeline {
    agent any

    environment {
        NODE_ENV = 'test'
    }

    stages {
        stage('Checkout') {
            steps {
                git 'https://github.com/user/repo.git'
            }
        }

        stage('Install') {
            steps {
                sh 'npm ci'
            }
        }

        stage('Lint') {
            steps {
                sh 'npm run lint'
            }
        }

        stage('Test') {
            steps {
                sh 'npm run test'
            }
        }

        stage('Build') {
            steps {
                sh 'npm run build'
            }
        }

        stage('Deploy') {
            steps {
                sh 'npm run deploy'
            }
        }
    }

    post {
        always {
            junit 'test-results.xml'
            publishHTML([
                reportDir: 'coverage',
                reportFiles: 'index.html',
                reportName: 'Coverage Report'
            ])
        }
        success {
            echo 'Deployment successful!'
        }
        failure {
            echo 'Pipeline failed!'
        }
    }
}
```

**Features:**
- Declarative and scripted pipelines
- Plugin ecosystem (1000+)
- Master-agent architecture
- Blue Ocean UI
- Distributed builds

```yaml

  only:
    - main
  environment:
    name: production
    url: https://example.com
```

**Advantages:**
- Built into GitLab platform
- Self-hosted or SaaS
- Container-native workflows
- Kubernetes integration
- Comprehensive security scanning

### CircleCI

Cloud-based CI platform:

```yaml
version: 2.1

orbs:
  node: circleci/node@5.0.0

jobs:
  build-and-test:
    docker:
      - image: cimg/node:18.0
    steps:
      - checkout
      - node/install-packages:
          pkg-manager: npm
          cache-version: v1
      - run:
          name: Run tests
          command: npm run test
      - run:
          name: Run build
          command: npm run build
      - store_artifacts:
          path: dist/
      - store_test_results:
          path: test-results/

workflows:
  build:
    jobs:
      - build-and-test
```

## Testing Automation

### Unit Testing

#### Jest (JavaScript)

```typescript
describe('Calculator', () => {
  it('should add two numbers correctly', () => {
    expect(add(2, 3)).toBe(5)
  })

  it('should handle negative numbers', () => {
    expect(add(-2, 3)).toBe(1)
  })
})
```

#### pytest (Python)

```python
import pytest

class TestCalculator:
    def test_add(self):
        assert add(2, 3) == 5

    @pytest.mark.parametrize("a,b,expected", [
        (2, 3, 5),
        (-2, 3, 1),
        (0, 0, 0)
    ])
    def test_add_parametrized(self, a, b, expected):
        assert add(a, b) == expected
```

### Integration Testing

```typescript
describe('User API Integration', () => {
  let server: Server
  let database: Database

  beforeAll(async () => {
    database = new Database(':memory:')
    server = new Server(database)
    await server.start()
  })

  afterAll(async () => {
    await server.close()
    await database.close()
  })

  it('should create and retrieve user', async () => {
    const response = await fetch('http://localhost:3000/users', {
      method: 'POST',
      body: JSON.stringify({ name: 'John' })
    })

    const user = await response.json()
    expect(user.id).toBeDefined()
    expect(user.name).toBe('John')

    // Verify in database
    const dbUser = await database.users.findById(user.id)
    expect(dbUser.name).toBe('John')
  })
})
```

### E2E Testing

#### Cypress

```javascript
describe('User Authentication', () => {
  beforeEach(() => {
    cy.visit('http://localhost:3000')
  })

  it('should allow user to login', () => {
    cy.get('[data-testid="email-input"]').type('user@example.com')
    cy.get('[data-testid="password-input"]').type('password123')
    cy.get('[data-testid="login-button"]').click()

    cy.url().should('include', '/dashboard')
    cy.get('[data-testid="user-profile"]').should('be.visible')
  })

  it('should show error for invalid credentials', () => {
    cy.get('[data-testid="email-input"]').type('user@example.com')
    cy.get('[data-testid="password-input"]').type('wrongpassword')
    cy.get('[data-testid="login-button"]').click()

    cy.get('[data-testid="error-message"]')
      .should('contain', 'Invalid credentials')
  })
})
```

#### Playwright

```typescript
import { test, expect } from '@playwright/test'

test('user authentication flow', async ({ page }) => {
  await page.goto('http://localhost:3000')

  await page.fill('[data-testid="email-input"]', 'user@example.com')
  await page.fill('[data-testid="password-input"]', 'password123')
  await page.click('[data-testid="login-button"]')

  await expect(page).toHaveURL(/.*dashboard/)
  await expect(page.locator('[data-testid="user-profile"]')).toBeVisible()
```

## Continuous Deployment

### Deployment Strategies

**Blue-Green Deployment:**
```
Current (Blue) → New Version (Green) → Traffic Switch
↓
Old (Blue) kept running for quick rollback
```

**Canary Deployment:**
```
Release to 5% of users → Monitor → 25% → 50% → 100%
                        ↓ Rollback if issues
```

**Rolling Deployment:**
```
Pod 1: Old → New
Pod 2: Old → New
Pod 3: Old → New
(Sequential, gradual update)
```

### Deployment Tools

#### Kubernetes

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: api-server
spec:
  replicas: 3
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  selector:
    matchLabels:
      app: api-server
  template:
    metadata:
      labels:
        app: api-server
    spec:
      containers:
      - name: api
        image: myregistry.azurecr.io/api:latest
        ports:
        - containerPort: 3000
        env:
        - name: NODE_ENV
          value: "production"
        resources:
          requests:
            memory: "256Mi"
            cpu: "250m"
          limits:
            memory: "512Mi"
            cpu: "500m"
        livenessProbe:
          httpGet:
            path: /health
            port: 3000
          initialDelaySeconds: 10
          periodSeconds: 10
```

## Pipeline Best Practices

1. **Fast Feedback**: Keep build time under 10 minutes
2. **Parallel Execution**: Run independent jobs in parallel
3. **Caching**: Cache dependencies to speed up builds
4. **Fail Fast**: Run quick checks before slow tests
5. **Clear Visibility**: Make build status easily visible
6. **Notifications**: Alert team on failures
7. **Retry Logic**: Automatic retry on flaky tests
8. **Environment Parity**: Match prod/test environments
