# Identity and Access Management (IAM)

Identity and Access Management (IAM) is a framework of business processes, policies, and technologies that facilitates the management of digital identities and controls user access to critical information within an organization. IAM ensures the right individuals access the right resources at the right times for the right reasons.

## Overview

Modern IAM systems provide centralized authentication, authorization, and access control across on-premises and cloud environments. They enable organizations to implement security best practices, maintain compliance, improve user experience, and reduce operational overhead through automation and self-service capabilities.

## Core IAM Components

### Identity Lifecycle Management

Managing user identities from creation through deletion:

**Identity Provisioning**:
- **Automated User Provisioning**: Creating accounts based on HR system triggers
- **Just-in-Time (JIT) Provisioning**: Creating accounts upon first authentication
- **Bulk Provisioning**: Mass account creation for onboarding
- **Role-based Provisioning**: Assigning access based on job roles
- **Workflow Automation**: Approval processes for access requests

**Identity Deprovisioning**:
- Automated account suspension on termination
- Grace periods for contractor/vendor offboarding
- Data retention and transfer procedures
- Access rights revocation across all systems
- Device and credential recovery

**Lifecycle Events**:
- New hire onboarding
- Role changes and transfers
- Leave of absence
- Return from leave
- Termination or resignation
- Contractor expiration

### Authentication

Verifying the identity of users and devices:

**Authentication Methods**:

**Password-Based Authentication**:
- Username and password
- Password policies (complexity, expiration, history)
- Password managers and vaults
- Self-service password reset (SSPR)

**Multi-Factor Authentication (MFA)**:
- **Knowledge Factors**: Something you know (password, PIN)
- **Possession Factors**: Something you have (phone, token, smart card)
- **Inherence Factors**: Something you are (biometrics)
- **Location Factors**: Somewhere you are (geolocation, network)
- **Time Factors**: Sometime you are (time-based access)

**Passwordless Authentication**:
- **Biometric Authentication**: Fingerprint, facial recognition, voice
- **Hardware Tokens**: FIDO2/WebAuthn security keys (YubiKey)
- **Push Notifications**: Mobile app approval (Microsoft Authenticator, Duo)
- **Magic Links**: Email or SMS one-time links
- **Passkeys**: Cryptographic credentials synced across devices

**Risk-Based Authentication**:
- Contextual analysis (location, device, behavior)
- Adaptive authentication strength
- Anomaly detection
- Step-up authentication for sensitive operations
- Continuous authentication

**Single Sign-On (SSO)**:
- **SAML 2.0**: XML-based federation protocol
- **OAuth 2.0**: Authorization framework for API access
- **OpenID Connect (OIDC)**: Authentication layer on OAuth 2.0
- **Kerberos**: Network authentication protocol
- **Web SSO**: Browser-based single sign-on
- **Mobile SSO**: Native app authentication
- **Desktop SSO**: Integrated Windows Authentication

**Certificate-Based Authentication**:
- Public Key Infrastructure (PKI)
- Smart cards and CAC cards
- Client SSL/TLS certificates
- Code signing certificates
- Device certificates

### Authorization

Determining what authenticated users are allowed to do:

**Authorization Models**:

**Role-Based Access Control (RBAC)**:
- Assign permissions to roles, users to roles
- Reduces complexity through role hierarchy
- Supports separation of duties (SoD)
- Role mining and optimization
- Least privilege principle

**Attribute-Based Access Control (ABAC)**:
- Policy-based access using attributes
- User attributes (department, clearance, location)
- Resource attributes (classification, owner)
- Environmental attributes (time, location, threat level)
- Dynamic and context-aware access decisions

**Policy-Based Access Control (PBAC)**:
- Centralized policy management
- Fine-grained access policies
- Policy decision points (PDP)
- Policy enforcement points (PEP)
- Policy administration points (PAP)

**Relationship-Based Access Control (ReBAC)**:
- Access based on relationships between entities
- Graph-based authorization
- Social network and collaboration permissions
- Resource ownership and sharing

**Access Control Lists (ACLs)**:
- Direct assignment of permissions to users
- File system and network ACLs
- Legacy systems support

### Privileged Access Management (PAM)

Securing and monitoring privileged accounts with elevated permissions:

**PAM Capabilities**:

**Privileged Account Discovery**:
- Automated discovery of privileged accounts
- Local admin accounts
- Service accounts
- Shared accounts
- Embedded credentials

**Password Vaulting**:
- Secure storage of privileged credentials
- Automated password rotation
- Check-out/check-in workflow
- Password randomization
- Emergency access procedures

**Session Management**:
- Privileged session recording
- Session monitoring and alerting
- Session isolation (jump servers)
- Just-in-Time (JIT) access provisioning
- Just-Enough-Access (JEA) principles
- Time-limited access grants

**Privilege Elevation**:
- Temporary elevation requests
- Approval workflows
- Sudo and RunAs management
- Application-to-application password management

**Secrets Management**:
- API keys and tokens
- Database credentials
- SSH keys
- Certificates
- Encryption keys
- Configuration secrets

## Zero Trust Architecture

Security model based on "never trust, always verify":

### Zero Trust Principles

1. **Verify Explicitly**: Always authenticate and authorize based on all available data points
2. **Use Least Privilege Access**: Limit user access with Just-In-Time and Just-Enough-Access
3. **Assume Breach**: Minimize blast radius and segment access; verify end-to-end encryption

### Zero Trust Components

**Identity Verification**:
- Strong authentication (MFA, passwordless)
- Continuous authentication and authorization
- Risk-based access policies
- User and entity behavior analytics (UEBA)

**Device Trust**:
- Device registration and compliance
- Endpoint security posture assessment
- Managed vs. unmanaged device policies
- Device health attestation
- Mobile Device Management (MDM)
- Endpoint Detection and Response (EDR)

**Network Segmentation**:
- Micro-segmentation
- Software-Defined Perimeter (SDP)
- Network Access Control (NAC)
- Zero Trust Network Access (ZTNA)
- VPN replacement with identity-based access

**Application Access**:
- Application-level authentication
- API security and gateway
- Per-application access policies
- Cloud Access Security Broker (CASB)

**Data Protection**:
- Data classification and labeling
- Encryption at rest and in transit
- Rights management and DRM
- Data Loss Prevention (DLP)

### Zero Trust Network Access (ZTNA)

Modern alternative to VPNs:

**ZTNA Architecture**:
- Identity-centric access
- Software-Defined Perimeter
- Invisible to attackers (no open ports)
- Application-level access granularity
- Continuous trust verification

**ZTNA Deployment Models**:
- **Client-based ZTNA**: Agent on endpoint devices
- **Clientless ZTNA**: Browser-based access
- **Service-based ZTNA**: Cloud-delivered service

**ZTNA Benefits**:
- Reduced attack surface
- Improved user experience
- Better visibility and control
- Simplified remote access
- Cloud and hybrid support

## IAM Security Best Practices

### Password Security

- Enforce strong password policies (NIST SP 800-63B)
- Implement password managers
- Eliminate password expiration (unless compromised)
- Screen against breached password databases
- Support passwordless authentication

### MFA Best Practices

- Require MFA for all users
- Use push notifications or hardware tokens
- Avoid SMS-based OTP (sim swapping risk)
- Implement phishing-resistant MFA
- Provide fallback authentication methods

### Access Control

- Implement least privilege access
- Use time-limited access grants
- Require approval for privileged access
- Regular access reviews and certifications
- Automated deprovisioning

### Monitoring and Auditing

- Log all authentication and authorization events
- Monitor for anomalous access patterns
- Alert on privilege escalation
- Track privileged session activity
- Retain logs for compliance
