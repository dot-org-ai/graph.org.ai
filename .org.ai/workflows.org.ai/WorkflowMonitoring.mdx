# Workflow Monitoring

Comprehensive monitoring and observability is critical for production workflows. This domain covers the practices, tools, and patterns for detecting issues, debugging problems, and maintaining reliability.

## Overview

Workflow monitoring transforms workflows from black boxes into observable systems. Through metrics, logs, traces, and alerts, organizations gain visibility into workflow execution and can proactively respond to issues.

## The Three Pillars: Metrics, Logs, Traces

### Metrics: Understanding Performance

Metrics are numerical time-series data that track workflow behavior.

**Key Workflow Metrics**:

```
Execution Metrics:
├─ workflow_execution_duration (histogram)
├─ workflow_executions_total (counter)
├─ workflow_executions_failed (counter)
├─ workflow_executions_succeeded (counter)
└─ workflow_executions_currently_running (gauge)

Activity Metrics:
├─ activity_execution_duration (histogram)
├─ activity_retries (counter)
├─ activity_failures (counter)
└─ activity_timeouts (counter)

Resource Metrics:
├─ workflow_execution_queue_size (gauge)
├─ worker_count (gauge)
├─ worker_availability (gauge)
└─ event_history_size (gauge)
```

### Tracing: Understanding the Path

Distributed tracing shows the full path of a workflow execution across services.

**Trace Structure**:
```
Workflow Execution (root trace)
├── Activity 1
│   ├── HTTP Request to Service A
│   ├── Database Query
│   └── Response Processing
├── Activity 2
│   ├── Message Queue Publish
│   └── Acknowledgment
└── Activity 3
    ├── Cache Lookup
    ├── Cache Miss → Database Query
    └── Cache Update
```

**Implementation (OpenTelemetry)**:

```typescript
import { getNodeAutoInstrumentations } from '@opentelemetry/auto-instrumentations-node';
import { JaegerExporter } from '@opentelemetry/exporter-trace-jaeger';

const sdk = new NodeSDK({
  instrumentations: [getNodeAutoInstrumentations()],
  traceExporter: new JaegerExporter({
    endpoint: 'http://localhost:14268/api/traces'
  })
});

sdk.start();

// In workflow activity
import { trace } from '@opentelemetry/api';

const tracer = trace.getTracer('workflow-tracer');

async function myActivity(input: ActivityInput): Promise<ActivityOutput> {
  const span = tracer.startSpan('myActivity', {
    attributes: {
      'workflow.id': workflowId,
      'activity.input': JSON.stringify(input)
    }
  });

  try {
    // Nested spans for sub-operations
    const userSpan = tracer.startSpan('fetch-user', {
      parent: span
    });
    const user = await fetchUser(input.userId);
    userSpan.end();

    const processSpan = tracer.startSpan('process-data', {
      parent: span
    });
    const result = processData(user);
    processSpan.end();

    span.setStatus({ code: SpanStatusCode.OK });
    return result;
  } catch (error) {
    span.recordException(error);
    span.setStatus({ code: SpanStatusCode.ERROR });
    throw error;
  } finally {
    span.end();
  }
}
```

## Retry Strategies

Intelligent retries are essential for handling transient failures.

### Exponential Backoff

Most common and recommended strategy.

```typescript
interface RetryPolicy {
  maxAttempts: number;
  initialDelay: number;      // milliseconds
  maxDelay: number;
  backoffMultiplier: number;
  jitterFraction?: number;    // 0.1 = 10% jitter
}

function calculateBackoff(
  attemptNumber: number,
  policy: RetryPolicy
): number {
  const exponentialDelay = policy.initialDelay *
    Math.pow(policy.backoffMultiplier, attemptNumber - 1);

  const cappedDelay = Math.min(exponentialDelay, policy.maxDelay);

  // Add jitter to prevent thundering herd
  const jitter = cappedDelay * (policy.jitterFraction ?? 0.1) *
    (Math.random() * 2 - 1);

  return cappedDelay + jitter;
}

// Example: exponential backoff configuration
const retryPolicy: RetryPolicy = {
  maxAttempts: 5,
  initialDelay: 100,        // 100ms
  maxDelay: 32000,          // 32s
  backoffMultiplier: 2,
  jitterFraction: 0.1
};

// Results in: 100ms, 200ms, 400ms, 800ms, 1600ms
```

### Circuit Breaker Pattern

Prevents cascading failures by stopping requests to failing services.

```typescript
enum CircuitState {
  CLOSED = 'closed',      // Normal operation
  OPEN = 'open',          // Failing, reject requests
  HALF_OPEN = 'half_open' // Testing recovery
}

class CircuitBreaker {
  private state: CircuitState = CircuitState.CLOSED;
  private failureCount: number = 0;
  private successCount: number = 0;
  private lastFailureTime: number = 0;

  constructor(
    private failureThreshold: number = 5,
    private successThreshold: number = 2,
    private timeout: number = 60000 // 1 minute
  ) {}

  async execute<T>(
    operation: () => Promise<T>
  ): Promise<T> {
    if (this.state === CircuitState.OPEN) {
      if (Date.now() - this.lastFailureTime > this.timeout) {
        this.state = CircuitState.HALF_OPEN;
        this.successCount = 0;
      } else {
        throw new Error('Circuit breaker is OPEN');
      }
    }

    try {
      const result = await operation();

      if (this.state === CircuitState.HALF_OPEN) {
        this.successCount++;
        if (this.successCount >= this.successThreshold) {
          this.state = CircuitState.CLOSED;
          this.failureCount = 0;
        }
      }

      return result;
    } catch (error) {
      this.failureCount++;
      this.lastFailureTime = Date.now();

      if (this.failureCount >= this.failureThreshold) {
        this.state = CircuitState.OPEN;
      }

      throw error;
    }
  }
}
```

### Dead Letter Queue Pattern

Captures failed messages for later analysis and replay.

```typescript
interface FailedWorkflowMessage {
  workflowId: string;
  workflowName: string;
  input: unknown;
  error: {
    message: string;
    stack: string;
    type: string;
  };
  attempts: number;
  firstFailureTime: string;
  lastFailureTime: string;
}

async function handleWorkflowFailure(
  error: Error,
  workflow: WorkflowExecution,
  attempts: number
): Promise<void> {
  // If max retries exceeded, send to DLQ
  if (attempts >= MAX_RETRY_ATTEMPTS) {
    const dlqMessage: FailedWorkflowMessage = {
      workflowId: workflow.id,
      workflowName: workflow.name,
      input: workflow.input,
      error: {
        message: error.message,
        stack: error.stack || '',
        type: error.constructor.name
      },
      attempts,
      firstFailureTime: workflow.createdAt.toISOString(),
      lastFailureTime: new Date().toISOString()
    };

    // Store in DLQ for investigation
    await deadLetterQueue.publish(dlqMessage);

    // Alert operations team
    await alerting.sendAlert({
      severity: 'critical',
      title: `Workflow ${workflow.name} exhausted retries`,
      message: error.message,
      context: dlqMessage
    });
  }
}
```

## Error Handling

### Error Classification

```typescript
enum ErrorType {
  // Transient: retry likely to succeed
  TRANSIENT = 'transient',
  // Permanent: retry will not help
  PERMANENT = 'permanent',
  // Unknown: uncertain if transient or permanent
  UNKNOWN = 'unknown'
}

function classifyError(error: Error): ErrorType {
  // Transient errors
  if (error instanceof TimeoutError) return ErrorType.TRANSIENT;
  if (error instanceof NetworkError) return ErrorType.TRANSIENT;
  if (error.message.includes('temporarily unavailable'))
    return ErrorType.TRANSIENT;

  // Permanent errors
  if (error instanceof ValidationError) return ErrorType.PERMANENT;
  if (error instanceof AuthenticationError) return ErrorType.PERMANENT;
  if (error instanceof NotFoundError) return ErrorType.PERMANENT;

  // Unknown
  return ErrorType.UNKNOWN;
}

// Retry decision based on error type
async function retryDecision(
  error: Error,
  attempts: number,
  policy: RetryPolicy
): Promise<boolean> {
  const errorType = classifyError(error);

  if (errorType === ErrorType.PERMANENT) {
    // Never retry permanent errors
    return false;
  }

  if (errorType === ErrorType.TRANSIENT) {
    // Always retry transient errors up to limit
    return attempts < policy.maxAttempts;
  }

  // For unknown errors, use conservative approach
  return attempts < 3;
}
```

### Compensation Transactions

Rolling back partial workflow execution on failure.

```typescript
async function orderWorkflow(order: Order): Promise<OrderResult> {
  const compensations: Array<() => Promise<void>> = [];

  try {
    // Reserve inventory
    const inventory = await activities.reserveInventory(order);
    compensations.push(() =>
      activities.releaseInventory(inventory)
    );

    // Process payment
    const payment = await activities.processPayment(order);
    compensations.push(() =>
      activities.refundPayment(payment)
    );

    // Ship order
    const shipment = await activities.shipOrder(order);
    // No compensation needed for shipment yet

    return { success: true, order, shipment };
  } catch (error) {
    // Execute compensations in reverse order
    for (const compensation of compensations.reverse()) {
      try {
        await compensation();
      } catch (compensationError) {
        logger.error('Compensation failed', {
          originalError: error,
          compensationError
        });
      }
    }

    throw error;
  }
}
```
