# MCP Client Integration

MCP Clients are applications that connect to MCP servers and consume their tools and resources. They manage server connections, discover capabilities, and present available tools to users and applications (particularly AI models like Claude).

### Dynamic Server Discovery

```typescript
class ServerRegistry {
  private servers = new Map<string, ServerConfig>()

  async discoverServers(): Promise<ServerInfo[]> {
    // Load from configuration
    const config = await loadConfig()
    const discovered: ServerInfo[] = []

    for (const [name, config] of Object.entries(config.mcpServers)) {
      try {
        const info = await this.probeServer(config)
        discovered.push({
          name,
          ...info
        })
      } catch (error) {
        console.error(`Failed to discover server ${name}:`, error)
      }
    }

    return discovered
  }

  private async probeServer(config: ServerConfig): Promise<ServerInfo> {
    const transport = this.createTransport(config)
    const client = new Client({...})

    try {
      await client.connect(transport)
      const tools = await client.listTools()
      const resources = await client.listResources()

      return {
        capabilities: { tools, resources },
        config
      }
    } finally {
      await client.close()
    }
  }
}
```

### Tool Caching & Optimization

```typescript
class CachingClient {
  private toolCache: Map<string, ToolInfo[]> = new Map()
  private cacheTTL = 5 * 60 * 1000  // 5 minutes

  async listTools(serverId: string): Promise<ToolInfo[]> {
    const cached = this.toolCache.get(serverId)
    if (cached) {
      return cached
    }

    const tools = await this.client.listTools()
    this.toolCache.set(serverId, tools)

    // Clear cache after TTL
    setTimeout(() => {
      this.toolCache.delete(serverId)
    }, this.cacheTTL)

    return tools
  }
}
```

## Connection Management

### Lifecycle Management

```typescript
class ManagedClient {
  private client: Client
  private transport: Transport
  private reconnectAttempts = 0
  private maxReconnectAttempts = 5
  private reconnectDelay = 1000

  async connect() {
    try {
      await this.client.connect(this.transport)
      this.reconnectAttempts = 0
      console.log('Connected to MCP server')
    } catch (error) {
      console.error('Connection failed:', error)
      this.scheduleReconnect()
    }
  }

  private scheduleReconnect() {
    if (this.reconnectAttempts >= this.maxReconnectAttempts) {
      console.error('Max reconnection attempts reached')
      return
    }

    this.reconnectAttempts++
    const delay = this.reconnectDelay * Math.pow(2, this.reconnectAttempts)

    setTimeout(() => {
      console.log(`Attempting reconnection (${this.reconnectAttempts}/${this.maxReconnectAttempts})`)
      this.connect()
    }, delay)
  }

  async disconnect() {
    try {
      await this.client.close()
      console.log('Disconnected from MCP server')
    } catch (error) {
      console.error('Disconnect error:', error)
    }
  }
}
```

## IDE Plugin Development

### VS Code Extension Example

```typescript
// extension.ts
import * as vscode from 'vscode'
import { Client } from '@modelcontextprotocol/sdk/client/index.js'

export class MCPExtension {
  private client: Client
  private provider: MCPCommandProvider

  async activate(context: vscode.ExtensionContext) {
    // Initialize client
    this.client = new Client({...})
    this.provider = new MCPCommandProvider(this.client)

    // Register command provider
    vscode.commands.registerCommand(
      'mcp.listTools',
      () => this.listTools()
    )

    // Add to command palette
    context.subscriptions.push(
      vscode.languages.registerCodeLensProvider('*', this.provider)
    )
  }

  private async listTools() {
    const tools = await this.client.listTools()
    const quickPick = vscode.window.createQuickPick()
    quickPick.items = tools.map(tool => ({
      label: tool.name,
      description: tool.description
    }))

    quickPick.onDidChangeSelection(async (selection) => {
      if (selection.length > 0) {
        await this.executeTool(selection[0].label)
      }
    })

    quickPick.show()
  }

  private async executeTool(toolName: string) {
    const result = await this.client.callTool({
      name: toolName,
      arguments: {}
    })

    vscode.window.showInformationMessage(
      `Tool executed: ${JSON.stringify(result.content)}`
    )
  }
}
```

## Error Handling & Resilience

### Request Error Handling

```typescript
async function safeToolCall(
  client: Client,
  toolName: string,
  args: unknown
): Promise<ToolResult | null> {
  try {
    const result = await client.callTool({
      name: toolName,
      arguments: args
    })

    if (result.isError) {
      console.error(`Tool error: ${result.content[0].text}`)
      return null
    }

    return result
  } catch (error) {
    if (error.code === 'TIMEOUT') {
      console.error('Tool execution timed out')
    } else if (error.code === 'CONNECTION_LOST') {
      console.error('Server connection lost')
    } else {
      console.error(`Unexpected error: ${error.message}`)
    }
    return null
  }
}
```

### Timeout Management

```typescript
class TimeoutClient {
  private defaultTimeout = 30000  // 30 seconds

  async callToolWithTimeout(
    toolName: string,
    args: unknown,
    timeout?: number
  ): Promise<ToolResult> {
    return Promise.race([
      this.client.callTool({ name: toolName, arguments: args }),
      this.delayedReject(timeout ?? this.defaultTimeout)
    ])
  }

  private delayedReject(ms: number): Promise<never> {
    return new Promise((_, reject) =>
      setTimeout(
        () => reject(new Error(`Tool call timed out after ${ms}ms`)),
        ms
      )
    )
  }
}
```

### Tool Capability Caching

```typescript
class CachedCapabilityClient {
  private capabilities: Map<string, ClientCapabilities> = new Map()
  private capabilityCacheTTL = 10 * 60 * 1000  // 10 minutes

  async getCapabilities(serverId: string): Promise<ClientCapabilities> {
    const cached = this.capabilities.get(serverId)
    if (cached?.timestamp && Date.now() - cached.timestamp < this.capabilityCacheTTL) {
      return cached
    }

    const tools = await this.client.listTools()
    const resources = await this.client.listResources()

    const capabilities = {
      tools,
      resources,
      timestamp: Date.now()
    }

    this.capabilities.set(serverId, capabilities)
    return capabilities
  }
}
```

## Logging & Debugging

### Request/Response Logging

```typescript
class LoggingClient {
  async callTool(request: CallToolRequest): Promise<ToolResult> {
    const id = crypto.randomUUID()
    console.log(`[${id}] Tool Call`, {
      tool: request.name,
      arguments: request.arguments,
      timestamp: new Date().toISOString()
    })

    const startTime = performance.now()

    try {
      const result = await this.client.callTool(request)
      const duration = performance.now() - startTime

      console.log(`[${id}] Tool Success`, {
        duration: `${duration.toFixed(2)}ms`,
        resultSize: JSON.stringify(result).length,
        isError: result.isError
      })

      return result
    } catch (error) {
      const duration = performance.now() - startTime

      console.error(`[${id}] Tool Error`, {
        duration: `${duration.toFixed(2)}ms`,
        error: error.message
      })

      throw error
    }
  }
}
```

## Best Practices

### Client Design

1. **Connection Pooling**: Reuse connections across requests
2. **Capability Caching**: Cache tool lists to reduce overhead
3. **Error Recovery**: Implement exponential backoff for retries
4. **Resource Cleanup**: Always close connections properly
5. **Logging**: Log all tool invocations for debugging

### Error Handling

1. **Graceful Degradation**: Handle missing tools gracefully
2. **Timeout Protection**: Always set timeouts on tool calls
3. **Error Messages**: Provide helpful error information
4. **Circuit Breaking**: Disable failing servers temporarily
5. **User Feedback**: Inform users of connectivity issues

### Performance

1. **Batch Operations**: Group requests when possible
2. **Lazy Loading**: Only connect to needed servers
3. **Resource Limits**: Implement rate limiting
4. **Monitoring**: Track performance metrics
5. **Optimization**: Profile and optimize slow operations
